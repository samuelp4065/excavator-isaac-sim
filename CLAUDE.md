# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A four-joint excavator robot (CAD → ROS 2 URDF package → USD) simulated in **NVIDIA Isaac Sim 5.1**, driven by a single Python joint-position controller. There is no build system, test suite, or linter wired up for the Isaac Sim side; the only executable code is `scripts/excavator_control.py` (automatic sweep demo) and `scripts/excavator_keyboard.py` (hold-key teleop for exploring joint angles; same setup, clamps in `JOINT_KEYS`), plus `scripts/run_live.py`, which keeps one Isaac Sim session open and hot-reloads `scripts/live_controller.py` (keyboard and sweep modes, `step(ctx)` API) whenever that file is saved. Prefer `run_live.py` for iterating; only edits to `run_live.py` itself need a restart.

## Running

Isaac Sim is a standalone install at `~/isaacsim`. Scripts must run under Isaac Sim's bundled interpreter, from the repo root:

```bash
~/isaacsim/python.sh scripts/excavator_control.py
```

- Not runnable with system `python`, and not from Isaac Sim's Script Editor: the script constructs its own `SimulationApp`.
- Close any open Isaac Sim GUI first; running both at once commonly crashes or freezes the machine (memory).
- `SimulationApp(...)` must be created **before** any other `isaacsim.*` / `omni.*` import. Keep that ordering in any new script.

## Architecture: the asset pipeline

The robot exists in several parallel representations under `Excavator_Final_description/urdf/`, and they are **not** kept in sync automatically:

1. `Excavator_Final.xacro` (+ `.trans`, `.gazebo`, `materials.xacro`): the original CAD-exporter output, used by the ROS 2 launch files (`launch/display.launch.py` for RViz, `launch/gazebo.launch.py`). Joints are named `Revolute 4`–`Revolute 7` (all `continuous`) and meshes use `file://$(find Excavator_Final_description)/...`.
2. `Excavator_Final.urdf`: hand-flattened copy used for the Isaac Sim import. Joints are renamed `swing_joint` / `arm_joint` / `pole_joint` / `bucket_joint` and mesh paths are relative (`../meshes/*.stl`) so the importer can resolve them without ROS.
3. `Excavator_Final/Excavator_Final.usd` (+ `configuration/*_base|physics|robot|sensor.usd`): generated by Isaac Sim's URDF importer (File → Import, **Fixed** base, joint drive **Position**). Binary; never hand-edit — re-import from the `.urdf` instead. Prefer `~/isaacsim/python.sh scripts/import_urdf.py` (headless, same settings, run with Isaac Sim closed). Importing via the GUI inside a running `run_live.py` session crashed mid-write once and left all five USD files empty (~492 bytes), which shows up as `Unresolved reference ... <defaultPrim>` / `Failed to find articulation`.

The control script loads only the USD, and looks joints up by name. Changing joint names, limits, or geometry means editing `Excavator_Final.urdf`, re-importing to regenerate the USD, updating the ranges/keys in the scripts (`JOINT_MOTION` / `JOINT_KEYS`, duplicated across `excavator_control.py`, `excavator_keyboard.py` and `live_controller.py`), and re-running `make_preview.py`. Mirror the change into the xacro if the ROS 2 side should match.

Kinematic chain: `base_link` → `swing_joint` (Z) → `base_joint_1_1` (cab) → `arm_joint` → `arm_1_1` → `pole_joint` → `Pole_1` → `bucket_joint` → `Bucket_1`. All joints are `continuous` (no limits), so the script's ranges are the only thing bounding motion. Meshes are in mm, scaled by 0.001.

## 3D preview for GitHub

`python3 scripts/make_preview.py` (system Python with numpy/matplotlib/Pillow, not Isaac Sim) assembles the per-link STLs at the zero pose using the URDF joint/visual origins and writes `docs/excavator.stl` (binary, opens in GitHub's 3D viewer) and `docs/excavator.png` (embedded in the README). It handles translations only and asserts all URDF `rpy` are zero.

## Control script notes

`scripts/excavator_control.py`: creates a `World`, references the USD at `/World/Excavator`, wraps it in `SingleArticulation`, sets drive gains (kp=1e4, kd=1e3), then each physics step sends cosine-eased position targets per joint (ranges/frequencies in `JOINT_MOTION`) via `ArticulationAction`. Exits early with a message if the USD hasn't been generated yet. If the arm oscillates, lower `kps` (e.g. 1e3); if the robot tips/slides, the USD was imported without a fixed base.

## ROS 2 package

`Excavator_Final_description` is an `ament_python` package (`colcon build`, `ros2 launch Excavator_Final_description display.launch.py`). Its `test/` directory contains only the stock ament copyright/flake8/pep257 checks.
